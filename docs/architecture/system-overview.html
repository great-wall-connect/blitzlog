Blitzlog · System architecture

How an autonomous agent runs from a labeled issue to a finished PR

A thin Packer-baked EC2 host wraps a single container. The container has no AWS credentials — all S3 work happens on the host. Three shutdown triggers (user / shutdown tool, EC2 spot interruption, and ECIM 2 reclamation) all funnel through one shared signal file so the agent's last work always reaches S3.

Workflow
GitHub
Trigger

Labeled GitHub issue

User attaches a trigger label (e.g. feat/issue-12-foo) to an issue. GitHub fires an issues.labeled webhook at the Lambda URL.

In assisted mode, the user also has a Telegram conversation with the bot — typed messages flow in via the Bot API.

AWS services
Orchestration · AWS Lambda

handler.py

  • Verifies GitHub webhook HMAC
  • Mints a GitHub App installation token
  • Acquires a free bot from the user's pool
  • Builds user-data (env, secrets, Tailscale)
  • Launches an EC2 spot instance with that user-data
EC2 HOST · PACKER-BAKED UBUNTU 26.04

Two systemd services

  • blitzlog-agent.service — runs watchdog.sh: loads baked image, runs container, watches /workspace/.shutdown, on container exit uploads logs + session archive to S3 and terminates the instance.
  • spot-watchdog.service — runs spot-watchdog.sh: polls IMDS for spot reclamation notices, touches /workspace/.interrupted on ACTION, exits.

Both services have IAM role access for S3 / EC2 — credentials never enter the container.

Shared signal files
Volume /workspace
Heartbeat

/.idle

Container's entrypoint touches this on boot. Cosmetic — host uses it as a "container is alive" marker.

Spot signal

/.interrupted

Written by spot-watchdog.service on the host when IMDS returns a spot reclamation notice. The container's spot_watchdog plugin polls every 5 s.

Shutdown signal

/.shutdown

Written by assisted-shutdown.sh (called from the shutdown tool OR the spot_watchdog plugin). Host's watchdog.sh watcher SIGTERMs the container on detection.

Session artifacts

/.blitzlog/*

session-archive-*.json + metadata.json. Container writes them; host's watchdog.sh uploads to S3 on container exit.
